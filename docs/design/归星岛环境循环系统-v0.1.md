## 一、Demo 季节压缩（解决"看不到季节"）

现有时间（已核实）：`1 现实分钟 ≈ 2 游戏小时`，一天约 8 分钟现实；30 分钟 ≈ 3~4 游戏日。

**Demo 模式：1 游戏日 = 1 季节推进单位**，玩家 30 分钟内看到四季：

| 游戏日 | 季节 |
|---|---|
| Day 1 | 春末 |
| Day 2 | 夏初 |
| Day 3 | 秋 |
| Day 4 | 冬 |

正式版恢复 `daysPerSeason = 7`。架构保留双模式：

```ts
const SEASON_CONFIG = {
  demo:   { daysPerSeason: 1 },
  normal: { daysPerSeason: 7 },
};
```

## 二、Season 只做计算层，不引入新时间源

现有存档已有 `world.day`（累计天数，已核实 SaveData.world.day）。**不新增存档字段**。

```ts
// season = getSeason(world.day)  纯函数派生，不保存
// demo: day % 4 → SPRING/SUMMER/AUTUMN/WINTER
// normal: floor((day-1)/7) % 4
```

好处：零存档改动、零兼容风险、不会出现"两个时间源打架"。

## 三、天气：事件表，不做概率

随机概率系统测试成本高、反馈不可控。改为**脚本化天气事件表**：每天睡醒，按 `(季节, 剧情进度, 星之碎片恢复程度)` 决定当天天气。

示例（第一章脚本）：

| 游戏日 | 天气 | 备注 |
|---|---|---|
| Day 1 | 晴 | 村长："今年春天来的有点晚。" |
| Day 2 | 小雨 | 夏雅："好久没有这么舒服的雨了。"（第一次雨） |
| Day 3 | 雾 | 森林特殊采集点（晨雾蘑菇，P1/P2） |
| 观星夜 | 星空 | 星夜：观星概率 + 隐藏对白 |

正式版再引入随机（复用同一天气状态结构）。

## 四、农业：不做季节限制（推翻原提案）

现状农业深度不足，反季节惩罚 = 玩家感受"限制"而非"策略"。v0.10 季节只影响：

1. **今日推荐种子**（商店推荐，纯引导不限制）
2. **环境视觉**（覆盖层/粒子，不换 Tilemap）
3. **特殊产物**（雨天蘑菇等，P1/P2）

作物季节限制等农业深化后再加。

## 五、绑定星之碎片（系统存在的理由）

天气/季节必须服务"归星岛复苏"，否则只是普通种田功能：

- 当前：归星岛季节混乱（"今年春天来的有点晚"）
- 碎片恢复后：天气趋于稳定、变"舒服"
- 第一次雨 → 夏雅对白；第一次星夜 → 阿风对白

玩家不是改变天气，而是**帮助这个地方恢复自己的节奏**——与星之碎片叙事方向（碎片=情绪/归属）一致。
