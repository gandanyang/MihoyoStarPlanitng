## 一、四类风险核查结果

### 1. 任务触发只判断条件、未判断"已完成状态" —— ⚠️ 部分存在

- 主线（questState）、剧情步骤（storyStep）、第一章进城（ch1TownIntroDone）、花园恢复（farm.restore）、支线试点（mapFlags）均已有"已完成态"判定，未发现条件式重复触发。
- 注意：`triggerTag`（归星记录事件标签）为**纯内存、不入档**（设计如此）——刷新后当天记录会缺标签，但不重复触发玩法。

### 2. 内存状态与存档状态不同步 —— ⚠️ 发现 1 处真实问题

- **E1/E9 清晨/傍晚夏雅偶遇**：`dawnXiyaDay / eveningXiyaDay` 是会话字段，只记"当天是否触发过"；**刷新后重置 → 同一天 6-8 时/18-20 时窗口内重新进游戏会再触发一次**。影响小（可重复的日常陪伴对白），但正是"重新进入重复触发"的原型。
- 其余模块（questState / storyStep / dailyQuest / mapFlags / album / automation / restore）在 `SaveSystem.apply()` 中均有恢复点，未发现"存了没恢复"的缺口。

### 3. 场景初始化重复执行 —— ⚠️ 与第 2 条同源

- 一次性事件大多挂在 `MapScene.create()` 的交互链上（靠近按 E 触发），多数已用持久化 flag 挡住；E1/E9 因会话字段重置成为例外（见上）。
- 旧机器人（FEATURE-036）曾有此风险，已用"背包持有 auto_farmer_robot > 0 则不再出现"兜底，无重复领取。

### 4. 存档版本/字段默认值导致重触发 —— ✅ 无风险

- 版本不匹配 → `migrate()` 直接清空旧档（v0.5 策略），不做"字段缺失默认空→重新触发"。
- `sanitize()` 只做非法值收敛，不改已完成状态。

## 三、已落地：统一一次性事件状态（小修）

新增 `src/systems/EventManager.ts`：

```ts
triggerOnce(id, fn)      // 未触发 → 执行 fn 并记录；已触发 → 跳过（返回 false）
hasTriggered(id)         // 只读
markTriggered(id)        // 手动标记（迁移/调试）
getGameEventSaveData()   // SaveSystem.save 序列化
restoreGameEventSaveData() // SaveSystem.apply 恢复（旧档默认空）
```

存档结构（可选字段，不升版本号，旧档默认空）：

```json
{ "gameState": { "triggeredEvents": { "xiya_garden_done": true } } }
```

接线：
- `SaveSystem`：SaveData.gameState? + save() + apply() + sanitize() 兜底。
- `window.debug.events`（triggerOnce / hasTriggered / markTriggered / getSaveData）供探针与调试。
- 探针 `tests/probes/probe-event-once.mjs`：内存幂等 + 存档往返 + 旧档兼容，8/8。
