## 〇、一句话定位

> **《归星物语》不是「种田赚钱游戏」，而是「资源驱动的归星岛复兴游戏」。**
> 玩家不是在经营一个岛，而是在**见证一个失去生命的地方重新拥有生命、重新拥有人的故事**。

（出处：`归星岛复兴循环-v0.10.md` 〇、`核心设计原则-世界复兴循环-v0.1.md` 〇）

## 一、核心体验（Core Fantasy）

### 1.1 玩家是谁

| 身份 | 说明 |
|------|------|
| 林澈（主角） | 被 AI 时代淘汰的程序员，27 岁，返乡 |
| 玩家角色定位 | **归乡者 / 修复者 / 连接过去与未来的人**（不是岛主 / 老板 / 资本经营者） |

### 1.2 玩家在做什么

> 回到一个逐渐衰败的地方，通过：农业、建设、资源采集、人与人的连接——让这里重新恢复生命。

（出处：`核心设计原则-世界复兴循环-v0.1.md` 一、二）

### 1.3 三条复兴线（互相解锁，非平行推进）

| 复兴线 | 玩家做 | 产生 | 对应系统 |
|--------|--------|------|----------|
| 资源复兴（物质） | 种田 / 砍树 / 挖矿 / 收集 | 建设值 / 复兴进度 | 农业 + 建设（worldRestore） |
| 人的复兴（关系） | 聊天 / 帮忙 / 参与事件 | 居民信任 | 关系记录 + NPC |
| 心的复兴（主线） | 探索碎片 / 爷爷遗物 / 自己的过去 | 林澈的变化 | 星之碎片 + 剧情 |

（出处：`归星岛复兴循环-v0.10.md` 一）

## 二、核心循环

### 2.1 推荐循环（长期主干）

```
玩家行动 → 环境变化 → 岛屿恢复 → 新的居民/机会出现
        → 新的能力与故事解锁 → 进一步改变岛屿
```

（出处：`核心设计原则-世界复兴循环-v0.1.md` 三）

### 2.2 复兴度框架（远期，v0.11+）

| 等级 | 状态 | 触发条件 |
|------|------|----------|
| Lv0 荒废 | 杂草丛生、居民离开 | 初始（夏雅 / 村长） |
| Lv1 初步恢复 | 农场恢复、房屋可住 | 完成第一章 + 农场恢复 + 房屋修复 |
| Lv2 小型社区 | 农业稳定、公共区域修复 | 多人任务完成 |
| Lv3 归星村 | 多区域恢复 | — |
| Lv4 星辰连接 | 后期 | — |

> 核对（Codex 2026-08-06）：复兴度可由 FEATURE-037 `worldRestore` 直接派生，**不新建存档字段**。

（出处：`岛屿复兴循环系统设计方案-v0.1.md` 二、九）

### 2.3 三层循环（现有，保留）

```
分钟级：移动 → 交互 → 即时反馈
日级：  06:00 起床 → 劳动/社交/交易（体力 100）→ 睡觉 → 结算 + 存档
章节级：序章（归乡）→ 第一章（居民/碎片）→ 第二章（星坠秘密）→ 第三章（归位）
```

（出处：`顶层设计.md` §3.1）

## 三、资源价值体系（v1.0 核心改造）

### 3.1 资源优先级（不是「获得 → 卖钱」）

```
自我需求 → 建设需求 → 任务需求 → 关系需求 → 剩余出售
```

| 资源 | 多价值流向 |
|------|-----------|
| 木头 | 修房 → 家具 → NPC 请求 → 出售 |
| 矿石 | 工具升级 → 建筑材料 → 科研 → 出售 |
| 食物 | 自己生活 → 分享居民 → 料理 → 出售 |

（出处：`核心设计原则-世界复兴循环-v0.1.md` 六、`岛屿复兴循环系统设计方案-v0.1.md` 四）

### 3.2 出售改造：智能出售（已立项 FEATURE-039，v0.10+）

一键出售 → **智能出售**（预览 + 关键资源保护 + 锁定）：

- `sellPriority`：normal（一键出售）/ reserve（跳过 + 提示：木材/石头/铁矿）/ forbidden（禁止：星之碎片/剧情物）
- 背包锁定 🔒 + 存档 `lockedItems`（可选字段，旧档兼容）
- 红线：不改经济数值、不重构背包

> 作用：为「资源 → 建设 → 羁绊 → 出售」循环打基础，防止玩家无脑卖光建设材料。

（出处：`智能出售系统升级方案-v0.1.md`）

### 3.3 v0.10 已落地的资源出口（作为 v1.0 支点）

- 3 个建设点：老屋修复 / 花园延续 / 后山道路修复（FEATURE-037 `worldRestore`）
- 作物双用途：卖 or 保留触发事件（不做料理）
- 矿石双出口：普通卖钱 / 稀有建设（v0.10 保持经济出口）

（出处：`顶层设计.md` §0 v0.6.6、`归星岛复兴循环-v0.10.md` 六）

## 四、NPC 与关系（v1.0 角色留存层）

### 4.1 NPC 原则

> **NPC 不是功能按钮——NPC = 世界恢复的证明。**

- ❌ NPC 出现 → 解锁商店
- ✅ 岛屿变化 → 吸引某类人回来 → 其能力与人生加入岛屿 → 产生新玩法

（出处：`核心设计原则-世界复兴循环-v0.1.md` 五）

### 4.2 NPC 回归机制（远期框架）

| NPC | 回归条件 | 功能 | 备注 |
|-----|----------|------|------|
| 木匠 | 修复房屋 / 仓库 | 房屋升级、家具 | **v0.11+ 唯一新增角色** |
| 铁匠 | 矿洞恢复 | 工具升级、矿石加工 | 可由矿工老张承接，避免重复 NPC |
| 花匠（小梅，已有） | 花园恢复 | 花卉、景观 | 已存在 |
| 技术员 | 后期 | 自动化升级 | 结合林澈程序员身份 |

（出处：`岛屿复兴循环系统设计方案-v0.1.md` 三、九）

### 4.3 关系成长（长期框架）

| 系统 | 定位 | 状态 |
|------|------|------|
| 关系记录系统 | 关系状态数据层（affinity / stage / memories，不显示数值） | Phase 1 方案已定稿 |
| 邀约系统 | 关系记录的「共同经历」扩展层：奖励 = **记忆**，非数值/金币 | 设计定稿，v1.0 入库储备 |
| NPC 生活化 | 日常对白 / 生活动作 / 日程错峰 | v0.6 已做 |

> 邀约核心句：**邀约不是为了增加好感，而是为了制造共同记忆。**
> 红线：无恋爱/结婚/约会模拟、无礼物体系、奖励 = 记忆。

（出处：`邀约系统规划-v0.1.md` 〇、一；`NPC好感系统规划-v0.1.md`）

### 4.4 矿工老张（已有角色，v1.0 潜在用途）

- 现有功能：矿洞 NPC、铁匠位承接候选（工具升级、矿石加工）
- 一句话小故事（Demo 定稿）："年轻的时候，我也想离开这里。"

（出处：`岛屿复兴循环系统设计方案-v0.1.md` 三、九；`顶层设计.md` §5.4-⑤）

## 五、定位校准：RPG × 模拟经营

### 5.1 参考系

- **星露谷** = 经营自己的农场（对照）
- **归星物语** = 经营一个逐渐重新有人的地方（本作）

（出处：`归星岛复兴循环-v0.10.md` 〇）

### 5.2 开罗游戏启发（已入库）

- 借鉴「建设 → 吸引居民 → 解锁功能 → 继续建设」正反馈循环
- 但**拒绝数值堆叠**：复兴等级/攻击力/金币 + N 不作为主要反馈（`核心设计原则` 八-1）

（出处：`岛屿复兴循环系统设计方案-v0.1.md` 〇、`核心设计原则-世界复兴循环-v0.1.md` 八）

### 5.3 设计过滤器（任何新系统上线前自问）

1. **Q1**：玩家做这个事情，世界有什么变化？
2. **Q2**：这个变化会影响哪些人？
3. **Q3**：这个变化是否产生新的可能？
4. **Q4**：如果删除金币，这个系统是否仍然有意义？

（出处：`核心设计原则-世界复兴循环-v0.1.md` 九）

## 六、世界成长：天气 / 季节（储备，未开工）

### 6.1 方向（2026-08-06 入库，v0.6.4 冲突登记）

- 28 天季节循环（春夏秋冬各 7 日）+ DailyWeather + 作物季节限制（软惩罚）+ 地图覆盖层 + 天气改变行为
- 主题结合：天气随碎片恢复趋于稳定

### 6.2 当前裁决（v0.6.5，已拍板实施的方向）

- 归星岛环境循环 = **世界反馈层**（非玩法系统）
- Demo 季节压缩：1 游戏日 = 1 季，30 分钟见四季；正式版 7 天/季，架构保留双模式
- `getSeason(world.day)` 纯计算层，**零存档改动**
- 天气事件表脚本化（Day1 晴·村长春迟 / Day2 小雨·夏雅 / Day3 雾 / 观星夜星夜·阿风），不做随机

### 6.3 当前 v0.10 落地范围（BUG-048）

- 雨天覆盖层 + 音效（复兴 = 核心 ★★★★★，天气 = 氛围 ★★★）
- 已实现：雨天自动湿润农田、雨声走 AmbienceSystem

> 完整季节系统 = v0.10 收口后立项，实施需制作人推翻冻结（v0.6.4 冲突登记在案）。

（出处：`顶层设计.md` §0 v0.6.4 / v0.6.5 / v0.6.8；`归星岛环境循环系统-v0.1.md`；`季节系统设计方向-v0.1.md`）
