# 《归星物语》季节系统设计方向 v0.1

> 状态：📋 **设计方向提案，未拍板实施**（来源：制作人 / GPT 讨论 2026-08-06）
> ⚠️ 冲突提示：与 v0.10 冻结项（制作人 2026-08-05：**不开新大系统**，天气/季节在禁止列表内）冲突；实施需制作人明确拍板
> 定位：核心系统方向，建议 **v0.10 收口后**立项，而非当前阶段施工

---

## 〇、设计目标

**不是模拟现实农业。**

目标是：让玩家感觉自己真的在这个地方生活了一段时间。

---

## 一、时间结构（与现有时间系统对齐）

现有时间流速（已核实）：`1 现实分钟 ≈ 2 游戏小时`，一天约 **8 分钟现实时间**（`src/config.ts`）。

建议季节结构（不照搬星露谷的一年 4×28 天长循环，压缩为 28 天完整循环）：

| 季节 | 天数 |
|---|---|
| 春季 | 第 1~7 天 |
| 夏季 | 第 8~14 天 |
| 秋季 | 第 15~21 天 |
| 冬季 | 第 22~28 天 |

一个完整循环 = **28 游戏日**。

理由：Demo 不是让玩家玩一年，而是短时间内感受到变化。

## 二、SeasonManager

新增 `SeasonManager.ts`：

```ts
enum Season { SPRING, SUMMER, AUTUMN, WINTER }
// 保存 currentSeason + seasonDay
```

存档新增（可选字段，旧档兼容，参照 `relations` 先例）：

```ts
{
  season: 'SPRING',
  dayOfSeason: 3
}
```

（现有存档已有 `world.day` 累计天数，可派生季节，建议二选一：存 season 冗余字段或纯派生，实施时定）

## 三、季节影响范围（先控三处，不全系统改）

### 1. 农业（核心）

作物定义（`CROP_DEFS`）增加季节字段：

```ts
season: ['spring']  // 萝卜：春秋 / 番茄：夏 / 玉米：夏秋 / 草莓：春
```

反季节种植**不禁止**，采用软惩罚：

- 生长速度降低
- 产量下降

保留策略空间。

> ⚠️ 前置风险（GPT 提醒，采纳）：季节会让农业问题暴露——"我为什么春天种这个？"必须与**作物差异化**一起做，否则季节只是徒增限制。

### 2. 地图表现（覆盖层，不换 Tilemap）

- 春：花朵增加、草色变化
- 夏：阳光更强、荷叶
- 秋：落叶粒子
- 冬：雾、冷色调

### 3. NPC 季节对白

新增 `seasonDialogue`：

- 夏雅·春："爷爷以前春天总会整理花园。"
- 夏雅·冬："小时候冬天最期待围炉聊天。"

## 四、天气系统（DailyWeather，不做真实天气）

每天睡醒生成（`DailyWeather`）：

```ts
enum Weather { SUNNY, RAIN, CLOUDY, FOG, STARLIGHT }
```

季节概率：

| 季节 | 概率 |
|---|---|
| 春 | 晴 60% / 雨 30% / 雾 10% |
| 夏 | 晴 70% / 雨 20% / 星夜 10% |
| 秋 | 晴 50% / 雾 20% / 雨 30% |
| 冬 | 晴 40% / 雪 30% / 雾 30% |

---

## 五、天气影响玩法（必须改变行为）

| 天气 | 影响 |
|---|---|
| 雨天 | 农田自动浇水，玩家获得时间去森林 |
| 雾天 | 森林出现特殊采集点（"晨雾蘑菇"） |
| 星夜 | 晚上观星概率增加，触发隐藏对白 |
| 暴雨（特殊事件） | 非每日，剧情使用（如修复房屋） |

---

## 六、与核心主题结合（重点）

**不要让天气只是天气，它服务"归星岛复苏"：**

- 初期：岛上天气混乱，村民说"以前这里的四季很准的"
- 随着星之碎片恢复：天气越来越稳定
- 后期：玩家不是改变天气，而是帮助这个地方**恢复自己的节奏**

与星之碎片叙事方向（碎片 = 归属/情绪，非力量）天然契合。

## 八、与当前阶段的关系（制作人决策点）

**方向与《归星物语》主题匹配，但存在阶段冲突：**

1. **v0.10 冻结**：制作人 2026-08-05 拍板"不开新大系统"，天气/季节在禁止列表内
2. **Demo 可见性**：一天 ≈ 8 分钟现实，15-30 分钟 Demo ≈ 3~4 游戏日——**玩家连一个季节都过不完**，季节系统在 Demo 中几乎不可见
3. **核心风险**：时间/作物/存档均为核心系统，Alpha 稳定期改动成本高

**建议**：作为 **v0.10 收口后**的核心系统立项（正式版/EA 方向），现在先入库设计方向。若制作人决定推进 v0.10 内实施，需正式推翻"天气冻结"并明确范围（建议只做第一阶段，且 Demo 内可用"季节加速/预览"方式展示）。
