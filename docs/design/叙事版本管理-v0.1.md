# 叙事版本管理规范 v0.1

> 立项：制作人 2026-08-04（起因：StorySystem 未登记剧情改动）
> 一句话：**剧情改动不是"代码修改"，是"叙事版本变更"**——要有版本号、有审批、有记录。

---

## 一、为什么需要这套机制

本次案例：P1 观星引导（制作人已拍板、`cae2e3f` 已提交）被直接替换成村长台词+新引导，探针同步了、但**没有提案、没有审批、没有记录**。

问题不在文案好坏，在于：**已拍板的叙事内容被当作普通代码行覆盖了。**

叙事文本 ≠ 代码。代码可以随意迭代；叙事是玩家情感的资产，覆盖 = 破坏版本。

## 二、三层结构（叙事资产必须三层同步）

```
叙事源（台词文档/人物圣经/适配分析）
   ↓ 实现
StorySystem.ts 等常量（渲染载体）
   ↓ 验证
探针 / 对话测试（行数、内容断言）
```

规则：**改实现必须同步源文档与探针；只改一层 = 变更不完整，不允许提交。**

## 三、变更分级

| 级别 | 内容 | 审批 | 示例 |
|---|---|---|---|
| **L1 快速通道** | 错别字/标点/称呼统一/提示措辞（不涉剧情含义） | 无需逐条，登记即可 | "庄园主"→口语；"系统通知"→"人事通知" |
| **L2 制作人审批** | 新增/修改台词含义、覆盖已拍板内容、影响情绪走向、涉角色设定 | 制作人拍板 | 本次观星引导替换 |
| **L3 双审+制作人** | 主线关键节点/结局/宇宙线真相/玩家选择 | 制作人+设计线 | 序章重构、观星夜选项 |

## 四、变更流程（提案制）

1. **提案**：谁 + 改什么 + 为什么 + 影响范围（源文档/探针/存档）
2. **分级**：L1 登记即可；L2/L3 进制作人审批
3. **登记持有**：按单写者制在控制台登记（StorySystem 等）
4. **施工**：实现 + 源文档 + 探针三层同步
5. **验证**：tsc + 相关探针 + 听感/文案复核
6. **落档**：叙事版本登记表 + CHANGELOG + 看板归档

| 版本号 | 日期 | 内容 | 级别 | 审批 | 提交 | 验证 |
|---|---|---|---|---|---|---|

## 六、与既有机制的关系

- **单写者制**：文件锁（StorySystem 等）——谁施工谁登记
- **剧情权限**：角色/世界观真相/关键节点 = L3，制作人+设计线
- **制作人看板**：叙事变更进"待验收区"，验收=拍板
- **Decision Override Rule**：覆盖已拍板内容必须重新走审批（本次案例即此）
