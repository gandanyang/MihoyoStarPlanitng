## 一、核心定位

玩家不是"收集图片"，而是**收集自己在这个地方生活过的证明**。

- 不做"图库/画廊"（那像开发者自嗨）
- 包装成《归星录·相簿》：玩家在归星岛生活过程中留下的记忆收藏
- 与已确定核心一致：*爷爷不是留下秘密的人，而是留下生活痕迹的人*

**与二游的关系**：它承担 CG 回收系统的职能，但不叫 CG，叫"回忆相簿"。
二游是"获得 CG"，我们是"获得一段回忆"。

## 二、功能结构（第一版）

```
归星录
├── 相簿      ← 第一版只做这个
├── 人物      （后续）
└── 回忆      （后续）
```

### 入口

- HUD 左上角「📖 归星录」按钮（所有地图场景可见，桌面/移动端均可点）
- 打开 → 相簿面板（半透明覆盖层，只读）

### 照片三要素（每张）

1. **标题**（如《夏日花园》，不是 image_023.png）
2. **描述**（一句话，如"雨停以后，小镇的屋檐会滴很久的水。"）
3. **获取来源**（如"完成「整理旧花园」"——玩家觉得"我解锁了一段经历"）

### 卡片两态

| 状态 | 表现 |
|---|---|
| 已解锁 | webp 图（16:9）+ 标题 + 描述 + 获得方式 |
| 未解锁 | 🔒 剪影占位（斜纹底）+ 获得方式提示（不剧透画面） |

## 四、技术落地

### 数据层：`src/data/PhotoAlbum.ts`

```ts
interface Photo {
  id: string;          // 如 'summer_garden'
  title: string;       // 如 '夏日花园'
  image: string;       // assets/photos/album/*.webp（16:9，≤1280，webp）
  description: string; // 一句话
  source: string;      // 获得方式文案
}
```

- `PHOTO_DATABASE`：3 张照片定义
- `unlockPhoto(id)` / `isPhotoUnlocked(id)` / `getAllPhotos()` / `getAlbumSaveData()` / `restoreAlbumSaveData(ids)`
- 存档：`SaveData.album?: string[]`（顶层可选字段，旧档无此字段视为空，兼容——同 FEATURE-039 lockedItems 模式）

### UI：`src/ui/PhotoAlbumPanel.ts`

- 模块级单例（同 ShopPanel/BackpackPanel 模式），DOM 只创建一次
- z-index 220（高于任务面板 215，低于对话层 500）
- 复用 `panelFadeIn/panelFadeOut`；Esc / 关闭按钮 / 点空白关闭
- 标题「📖 归星录 / 相簿」+ 副标题"已解锁 x/3 · 在这座岛上生活过的证明"

### 接线：`src/scenes/MapScene.ts`

- HUD `album-btn`（左上 top:78px，seed-switch-btn 下方，所有场景可见）
- `openPhotoAlbum()` 打开；update 冻结玩家移动；`handleBackButton` 返回键层级（endingPanel → photoAlbumPanel → shopPanel → ...）
- 3 个解锁触发点调用 `unlockPhoto`

### 图片资源：`assets/photos/album/*.webp`

- 来源：ComfyUI 宣发美图（round2/round3 批次）经 ffmpeg 转码
- 规格：**1280×720（16:9），libwebp q80**，38-75KB/张（移动端友好）
- 当前映射：
  - summer_garden ← round2_01_garden.png（林澈+夏雅农舍种田）
  - old_mine ← round3_02_mine.png（夏雅矿洞探索）
  - hillside_view ← round3_01_old_tree.png（林澈后山老树）

## 五、支线任务 vs 现有经历的落点说明（重要）

用户原设计是"绑定支线任务完成"（夏雅《整理旧花园》/老张矿洞/阿风后山观景）。
**当前项目支线任务系统为占位**（QuestPanel「支线」tab 显示"敬请期待"；`docs/design/支线任务扩充方案-v0.1.md` 为 📋 方案待拍板）。

实现决策：
- **落点绑定现有已实现的经历**（花园恢复/矿洞开采/后山老树），语义与用户设计一致（都是"完成某段经历"），但不依赖未落地的支线系统
- 获得方式文案按用户设计措辞（"完成「整理旧花园」"等），未来支线系统落地后**可平滑切换**（把触发点从现有系统挪到支线完成回调即可，数据/UI 零改动）
