## 〇、与关系记录系统的关系（先对齐，再设计）

邀约系统不是独立新玩法，它是**关系记录系统的「共同经历 / 事件」扩展层**：

```
关系记录系统 Phase 1（数据 + 存档 + 聊天 + 阶段 + 夏雅测试事件）
        ↓ 在其上挂载
邀约系统（邀请选项 → 事件机会 → 专属剧情 → Memory 记忆）
        ↓ 剧情播放
现有叙事挂点（StorySystem 单写者制 + 叙事版本管理）
```

职责分离：

| 系统 | 管什么 | 不管什么 |
|---|---|---|
| 关系记录（Phase 1） | 关系状态：affinity / stage / memories | 事件生成 |
| InviteSystem（本规划） | 生成事件机会：可邀请判断 / 创建事件 / 完成状态 | 播放故事 |
| 叙事管线 | 播放故事（对白/演出/语音） | 条件判断 |

继承红线（不可突破）：

- ❌ 不显示数值（玩家只看到阶段名 + 记忆）
- ❌ 奖励 = 记忆，不是数值 / 金币 / 稀有资源
- ❌ 无恋爱 / 结婚 / 约会模拟
- ❌ 无礼物体系（本次不设计「赠送」入口）
- ❌ 无 NPC 关系网 / 多人邀约

---

## 一、系统定位

### 名称

- 内部：**NPC 同行事件系统**
- 玩家表现："邀请夏雅一起去看看星星。"

不叫：约会系统 / 邀约玩法 / 好感解锁。

### MVP 目标（只验证三个问题）

1. 玩家是否愿意主动找 NPC？
2. NPC 陪伴是否提升角色记忆？
3. 事件是否比普通聊天更有价值？

服务对象排序：**角色塑造 > 共同记忆 > 关系数值**，而不是"刷好感 → 解锁奖励"。

---

## 二、核心循环

```
认识 NPC → 关系达到条件 → 出现邀请选项 → 选择地点
        → 触发专属事件 → 获得 Memory 记录 → 关系阶段推进（内部）
```

循环里的"奖励"是记忆与后续对白变化，玩家感受是"我经历过这件事"，不是"我刷过数值"。

---

## 三、MVP 范围

### 只做 1 个 NPC：夏雅

原因：她是目前人设最完整的角色（夏雅圣经 v1.3 关系曲线 5 节点已就绪）。**不做全村**。

### 只做 3 种邀约类型

| # | 类型 | 地点 | 内容 | 定位 |
|---|---|---|---|---|
| 1 | 散步 | 庄园 / 花田 / 河边 | 纯剧情，无特殊玩法 | 最低成本，建立"同行感" |
| 2 | 看星星 | 观星点 | 星空 + 对话 + 回忆（晚上触发） | 核心事件，主题承载 |
| 3 | 整理旧物 | 室内 | 翻找爷爷留下的东西 → 记忆碎片 | 连接爷爷线 + 记忆解锁 |

### 与夏雅关系曲线的映射（对齐夏雅圣经）

| 邀约事件 | 对应关系阶段 | 说明 |
|---|---|---|
| 散步 | 熟悉（stage 1） | "这个人开始愿意一起走走" |
| 整理旧物 | 理解（stage 2） | "她愿意带你看爷爷留下的东西" |
| 看星星 | 理解 ~ 羁绊（stage 2-3） | "你们已经是可以一起看星空的人了"（≠恋爱） |

## 四、邀请条件

不做复杂条件系统。MVP 对齐关系记录系统的阶段定义：

```ts
interface InviteCondition {
  npcId: string;
  minAffinity: number;      // 内部数值，0~100，不展示
  requiredQuest?: string;   // 可选：主线前置
  timeWindow?: 'day' | 'evening' | 'night'; // 可选：时段
}
```

示例（夏雅）：

| 事件 | 条件 |
|---|---|
| 散步 | affinity ≥ 10（相识后不久） |
| 看星星 | affinity ≥ 30（熟悉）+ 完成第一章 + 20:00 后 |
| 整理旧物 | affinity ≥ 30 + 庄园整理阶段推进（复用现有任务状态） |

## 五、数据结构设计

### InviteConfig

```ts
interface InviteConfig {
  id: 'xiya_stargaze';
  npc: 'xiya';
  location: 'farm_star';
  condition: { affinity: 30; timeWindow: 'night' };
  dialogue: 'INVITE_XIYA_STAR';
  reward: {
    memory: 'xiya_star_01';   // 真正的奖励
    affinityDelta: 5;          // 内部上调，不展示
  };
}
```

### Memory（复用关系记录系统的 memories 概念）

```ts
interface Memory {
  id: 'xiya_star_01';
  title: '第一次一起看星星';
  description: '夏雅告诉林澈，爷爷以前也喜欢坐在那里看天空。';
}
```

### InviteSystem 职责

- 判断是否可邀请（affinity / quest / 时段 / 是否已完成）
- 创建事件（复用现有事件触发机制）
- 保存完成状态（`relations.unlockedEvents` / `relations.memories`，**复用 Phase 1 存档字段，不新增大结构**）

## 六、UI（MVP，最小化）

不做大菜单，不做"邀约列表"（太手游）。

NPC 交互面板（对齐现有 NPC 交互入口）：

```
聊天
邀请
```

（「赠送」本次不做——项目红线无礼物系统，留给未来另行立项。）

点击邀请：

- 不可用 → "她今天似乎还有事情。"
- 可用 → 进入同行事件

## 七、奖励设计

**禁止：** 金币 / 稀有资源 / 数值播报。

**奖励：**

1. **Memory**（永久记录，关系记录系统的核心奖励）
2. **新对白**（完成后互动变化，例如：夜晚再遇到夏雅 → "这里的星星，还是和那天一样亮。"）
3. **小装饰 / 环境变化**（可选，P2：观星点或花园出现一个小物件，呼应"世界记住玩家"）

## 十、验收标准（MVP 完成定义）

玩家可以：

✅ 找夏雅 → 看到邀请选项
✅ 满足条件后邀请成功
✅ 触发专属剧情
✅ 完成后永久记录（Memory）
✅ 下次互动产生变化（新对白）

---

## 十一、施工注意（边界与权限）

- **InviteSystem 不直接播放剧情**：事件内容挂现有叙事挂点；涉及 StorySystem / StoryDialogue 的改动遵守单写者制
- **事件文案属剧情权限**（角色身份 / 关键剧情节点 / 玩家选择）→ 走叙事版本管理，制作人确认后施工
- **存档**：复用 `relations.memories / unlockedEvents`；若确需新增 `completedInvites` 字段，需 SaveSystem 专项批准（存档改动 = P0 敏感）
- **与 M1 可变探索空间衔接**（远期）：整理旧物事件可挂在"仓库/花园恢复"开放后，让邀约同时驱动地图变化
