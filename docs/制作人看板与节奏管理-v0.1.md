> 适用：Alpha 稳定期，多 AI Agent 并行（Codex / OpenCode / Trae）

## 一、设计原则：为什么不用 Todo / Doing / Done

当前项目已经过了"缺开发力"的阶段，真正的风险是四个：

1. **任务并行过多**——同一时刻多个 Agent 在动，互相看不见；
2. **修改互相影响**——文件级冲突、语义级回归；
3. **制作人无法及时验收**——产出堆积，做完没人拍板；
4. **方向容易扩散**——每个 Agent 按自己的理解"顺手优化"。

所以看板不是任务分发器，而是**制作人的风险与验收仪表盘**。它回答四个问题：

- 这活服务当前版本目标吗？（防扩散）
- 做完有人验收吗？（防积压）
- 会不会撞别人的文件？（防冲突）
- 值不值得现在做？（防并行过多）

看板上的最小单位是**工作包**，不是一句话待办。一个工作包必须有：

| 字段 | 说明 |
|---|---|
| 目标 | 一句话：做出什么、给谁用 |
| 验收点 | 可验证的完成标准（探针/真机/目测） |
| 负责人 | 单一 Agent（或明确的主责+协作者） |
| 涉及文件 | 领地清单，开工前与工作区核对 |
| 预估/已耗 | 时间盒，超时自动升级 |
| 状态 | 见下七区 |

## 二、看板结构（制作人视角，七区）

### 1. 当前版本目标（北极星）

看板最顶上一格，永远只有一段话 + 完成定义（DoD）。

```
当前版本目标：v0.6.x 主线语音接入 + 美术补齐 + 测试轮次 01 收尾
DoD：语音播放接入且验收通过 ｜ 立绘/主角精灵替换验收通过 ｜ 批2/批3 测试完成 ｜ 返回标题修复
版本边界（不做）：战斗 / 抽卡 / 新地图 / 新系统 / 世界观真相
```

规则：

- 任何工作包进入施工区前，先过这一格：**它服务当前目标吗？**
- 版本目标只能由制作人改写；Agent 提议须进"灵感池"。

### 2. 施工区（在途工作包）

同一时刻的活跃工作包。每包标注：负责人、涉及文件、预计完成、阻塞项。

规则：

- **单 Agent 在途上限 2 包**（超出必须挂起一个）；
- 开工前必须 `git status` 核对领地；
- 一个工作包拆开的提交要小而频，做完立即移入待验收区；
- 卡住 > 4 小时 → 自动升级到风险区并通知制作人。

### 3. 待验收区（制作人决策队列）

**这是全看板最重要的区**——防"做完没人看"。

每包带验收证据：提交号 / 探针结果 / 截图路径 / 真机步骤。

验收只有三种结果：

| 结果 | 含义 | 后续 |
|---|---|---|
| ✅ 接受 | 制作人拍板通过 | 移入历史归档 |
| 🔁 打回 | 不达标，附明确理由 | 退回施工区（同一负责人），附修改点 |
| 🟡 部分接受 | 主体 OK、细节待改 | 记一个 P2 收尾包，主体归档 |

规则：

- 打回**必须附理由**（一句话都行），不允许无声退回；
- 待验收区 > 3 包时，施工区停止新增（见"禁止开新功能"）。

### 4. 冻结区

明确冻结的事项，Agent **不得触碰**，除非制作人解冻。

当前冻结清单（示例）：

| 冻结项 | 解冻条件 |
|---|---|
| StorySystem.ts 无协调并发修改（单写者制） | 制作人授权/登记持有 |
| 音乐方向 | 风格方向确认后 |
| 机器人/美术/宇宙线（历史红线） | 制作人拍板 |

### 5. 风险区

每张风险卡：描述 / 等级（高-中-低）/ 缓解 / 责任人 / 状态。

当前已知风险（示例）：

| 风险 | 等级 | 缓解 | 状态 |
|---|---|---|---|
| 多线碰 StoryDialogue/StorySystem | 高 | 单写者制 + 领地登记 | 在控 |
| 语音接入与美术接线同文件在途 | 中 | 语音线统一收尾提交 | 观察 |
| 待验收积压 | 中 | 每日验收仪式 | 观察 |
| Fish API 额度为 0 | 低 | 本地 VoxCPM 管线 | 已规避 |
| VoxCPM 短句漂移 | 中 | 音高自检 | 已规避 |

### 6. 灵感池（非承诺区）

所有"以后可能做"的想法、设计方向、Agent 提议，**只记录不承诺**。

每周筛选一次：上日程 → 移入施工区规划；不上的 → 保留或删除。

当前池子（示例）：花田优化细化、M1 可变探索区域、好感系统 Phase2、第二章剧情、观星台恢复。

### 7. 历史归档（只读）

已验收完成的工作包，含：完成日期 / 提交号 / 验收人 / 一句话结果。

只读，禁止翻案重开（重开必须走灵感池重新立项）。

## 三、节奏管理：制作人检查流程

### 每日（15 分钟，建议固定时段）

1. **待验收区清零**：昨天完成的包，逐包验收（接受/打回/部分接受）；打回附理由；
2. **风险区扫一眼**：新风险？缓解措施生效了没？
3. **施工区看一眼**：有没有卡住（>4h）、有没有越界（动到别人领地）、有没有超并行上限；
4. **git status 抽查**：有没有无登记的在途文件（重点：StorySystem / StoryDialogue / SaveSystem / MapScene）。

### 每周（60 分钟，建议周一或周五）

1. **版本目标对表**：本周交付是否服务当前目标？有没有悄悄扩散；
2. **待验收积压复盘**：为什么积压？流程问题还是验收太严；
3. **灵感池筛选**：上日程 / 保留 / 删除；
4. **冻结区复查**：有没有可以解冻的（如音乐方向确认）；
5. **下周节奏**：并行面收窄还是放宽（依据待验收区水位）；
6. **归档补全**：本周验收的包全部进历史归档。

### 关键仪式

- **验收即拍板**：制作人不验收 = 工作包不算完成；
- **打回必附理由**：避免 Agent 空转；
- **每周一次方向对表**：防止"每个 Agent 顺手优化"导致风格/系统扩散。

## 四、AI Agent 调度规则

### 1. 什么任务可以并行

同时满足以下条件的可以并行：

- **文件领地不重叠**：涉及文件清单无交集（开工前 git status 确认）；
- **无依赖链**：A 的产出不是 B 的前置，或依赖已提交完成；
- **各自有独立验收点**：能单独验收，不依赖其他包的产出；
- **制作人验收水位允许**：待验收区 ≤ 3 包；
- **单 Agent 在途 ≤ 2 包**。

典型可并行组合：文档/规范 + UI 实现 + 测试脚本、不同地图瓦片、立绘（不同角色）。

### 2. 什么文件必须单负责人（Single-Writer）

| 文件/系统 | 原因 | 规则 |
|---|---|---|
| `StorySystem.ts` | 剧情常量+状态，多线碰撞高 | 单写者制（已立），登记持有 |
| `SaveSystem.ts` / 存档结构 | 存档损坏 = P0 | 禁止并行，改动需专项批准 |
| `MapScene.ts` | 全局场景，撞车概率最高 | 单写者制 |
| `StoryDialogue.ts` | 语音+立绘接线在途 | 当前语音线持有，其他人避让 |
| `Economy.ts` | 经济数值=唯一价格源 | 单写者制 |
| `assets/tiles/*` | 地图语义（gid/碰撞） | 单写者制 |

规则：开工前 `git status` + 控制台登记 → 改完即提交 → 注销。**一个文件同一时刻只有一个主人。**

### 3. 什么情况下禁止开新功能（STOP 条件）

满足任一即禁止新增工作包，Agent 只做收尾/修复/验收准备：

1. **待验收区 > 3 包**（先消化再开新）；
2. **当前版本 DoD 未达成**且开工中的包已 ≥ 4；
3. **未经制作人立项**的新系统/新角色/新玩法/新地图；
4. 涉及**剧情权限**（主角成长/角色身份/世界观真相/关键节点/玩家选择）的扩展；
5. 触碰**红区**（存档结构/战斗/抽卡/架构重构/技术方案替换）；
6. 同一文件已有他人未提交改动（无协调并发）。

### 4. 工作包生命周期

```
灵感池 →（制作人每周筛选）→ 施工区规划
         →（制作人批准/批次自动入队）→ 施工区（1 Agent，≤2 包）
         →（自测通过 + 提交）→ 待验收区（带证据）
         →（制作人验收：接受/打回/部分接受）→ 历史归档 / 退回施工区
```

### 5. 任务派发纪律（防重复派发）

**漏洞来源（案例复盘 2026-08-04）**：同一份"主线剧情语音生成"任务先派给一个 Agent，稍后又派给另一个 Agent。双方各自开工，产出两套批量脚本与两套音频（互为兜底但浪费工时），并在工作区留下重复/散落产物。

**三条纪律（必须写进每次派发）：**

1. **派发先查台账**：派发任何任务前，先看"施工区"是否已登记该任务。已登记 → 不重复派，只发追加指令；未登记 → 派发时登记：任务名 + **唯一负责人** + 涉及文件 + 开始时间。
2. **Agent 认领三查**（收到任务、动手之前）：
   - 查看板/任务卡：该任务是否已有负责人？有 → 停下问制作人，不抢跑；
   - 查工作区 `git status`：是否已有该任务的半成品/在途文件？有 → 说明已有人在做，停下对账；
   - 查 `tools/` 是否已有同类脚本：已有 → 复用，不重造一套。
3. **重复派发兜底协议**：一旦发现重复派发——双方先停手，**未裁定前任何一方不提交**（未提交 = 可无损合并）；制作人裁定保留哪份（或互为兜底），另一份挂起标记。

> 允许的例外：制作人**主动双线验证**（同一任务两条线各出一版做对比验收）时，必须在看板登记"双线模式 + 对比验收点"，两条线相互可见、领地错开。

1. 把 `docs/制作人控制台.md` 升级为本文档的七区格式（保留其"队列/避让"信息）；

   - 待验收区：语音接入收尾包、美术批（立绘/精灵）、FEATURE-036 回归补跑；
   - 冻结区：StorySystem 无协调修改、音乐方向、机器人/美术/宇宙线红线；
   - 风险区：见上文示例；

3. 制作人每日 15 分钟按第三节流程跑；
4. 两周后复盘：看板是否减少了"做完没人看"和"方向扩散"。

| 项 | 内容 |
