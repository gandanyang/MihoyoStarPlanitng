# 《归星物语》开发约束与架构入口

> 目的：防止 AI / 开发过程中**重复创建类似系统**。新增功能前必须检查已有能力，不允许无理由创建平行实现。
> 阅读顺序：`docs/AI开发前必读.md`（门禁）→ 本文件 → 对应任务文档（`docs/tasks/…`）。

---

## 一、核心原则

### 1. 状态不要散落

禁止分别用 `localStorage.xxx` / `scene.xxx` / `global.xxx` 保存同一种游戏状态。

所有持久状态必须收口到 **`SaveSystem`**（`SaveData` 结构：player / world / farm / story / mapFlags / album / gameState.triggeredEvents）。

- 场景内需要持久化的状态走 `MapSceneFlags`（随 `SaveSystem` 序列化，旧档可选字段默认空）。
- 会话级状态（刷新即丢）必须注释说明"仅本次游玩"，不得冒充存档状态。

### 2. 一次性事件统一入口

以下内容**必须优先使用 `EventManager.triggerOnce(id, fn)`**：

- 剧情触发 / NPC 特殊事件 / 相簿解锁 / 记忆卡获取 / 隐藏彩蛋 / 支线完成奖励

禁止只判断条件就触发而不记录"已触发"：

```ts
// ❌ 只判断条件，刷新后可能重复触发
if (day === 3) { triggerEvent(); }
```

必须：

```ts
// ✅ 触发一次 + 状态随存档恢复
EventManager.triggerOnce('event_id', () => { runEvent(); save(); });
```

## 二、新增系统前检查清单

执行任务前必须回答：

1. **是否已有类似功能？** 先查 `src/systems/`、`src/data/`、`docs/tasks/`、`docs/design/`。
2. **数据放哪里？**

   | 类型 | 位置 |
   | --- | --- |
   | 永久状态 | `SaveSystem`（SaveData / mapFlags / gameState） |
   | 配置数据 | `src/config` / `src/data` |
   | 临时表现 | scene / local（刷新即丢，需注释） |
   | UI 状态 | UI 层（`src/ui`） |

3. **是否可以扩展已有系统**（修改）而不是新增平行实现（NewSystem2）？

## 三、当前核心系统地图（入口）

| 能力 | 入口文件 | 负责 |
| --- | --- | --- |
| 存档 | `src/systems/SaveSystem.ts` | 玩家/世界/解锁/一次性事件状态（SaveData） |
| 剧情 | `src/systems/StorySystem.ts` | 主线步骤 storyStep、剧情对白数据 |
| 主线任务 | `src/systems/QuestSystem.ts` | 星之碎片任务状态机 |
| 每日任务 | `src/systems/DailyQuestSystem.ts` | 每日随机任务池 |
| 一次性事件 | `src/systems/EventManager.ts` | triggerOnce / hasTriggered / 存档恢复 |
| 解锁 / 相簿 | `src/data/PhotoAlbum.ts` | unlockPhoto（幂等）+ album 存档 |
| 场景一次性 flag | `MapSceneFlags`（`src/scenes/MapScene.ts`） | 场景状态随存档持久化 |
| 世界恢复 | `src/data/FarmRestore.ts` | 花园/老屋/道路恢复状态 |
| NPC | `src/systems/NPCSystem.ts` | NPC 作息 / 站位 |
| 音效氛围 | `src/systems/AmbienceSystem.ts` | 昼夜/雨天环境音 |
| Debug | `main.ts` 的 `window.debug` | 测试钩子（探针用） |

## 四、AI 开发规则

收到需求时**不要直接编码**，先输出：

```diff
已有系统检查:
- 是否存在类似功能:
- 复用方案:
- 新增文件:
- 修改文件:
```

确认后再施工。施工前先读相关文件，找最小修改点。

---

## 五、禁止事项

1. 新建第二个 `SaveManager` / `SaveSystem2`。
2. 新建第二个 `EventManager` / `EventService` / `QuestTrigger`。
3. 在 Scene 里直接写 `localStorage` / `global` 保存永久状态。
4. 用临时变量代替存档状态（会话级需注释并接受刷新丢失）。
5. 为单个 NPC 创建独立管理器（除非明确需要）。
6. 无任务要求的"行为不变重构"（稳定优先，重构需任务明确收口目标）。
