## 3. 关键发现：public/ 顶层存在 2 个孤儿文件

### 3.1 嫌疑文件清单

| 文件 | 尺寸 | 引入 commit | 代码引用 |
|------|------|-----------|---------|
| [public/character_choices.png](../../public/character_choices.png) | 640 × 336 | `bd88d80` (v0.25 阶段) | ❌ 全项目零引用 |
| [public/player_frames.png](../../public/player_frames.png) | 384 × 464 | `bd88d80` (v0.25 阶段) | ❌ 全项目零引用 |

### 3.2 验证方式

跨整个项目（src/ + tests/ + docs/ + *.html + *.css）grep 搜索 `character_choices|player_frames`：

```
搜索结果：No matches found
```

即：**没有任何 .ts / .css / .html / .mjs / .json 文件引用这两个 PNG**。

### 3.3 这是历史遗留孤儿文件

引入 commit `bd88d80` 标题：`0.25 核心系统：存档持久化 + 音效 + 背包 + 经验HUD + 美术升级`

特征：
- 文件名 `character_choices.png`（角色选择图）暗示早期想做"角色选择"功能
- 文件名 `player_frames.png`（玩家帧图）暗示早期玩家精灵的源图
- 现有 [src/scenes/StationScene.ts#L50](../../src/scenes/StationScene.ts) 和 [MapScene.ts#L227](../../src/scenes/MapScene.ts) 都加载 `assets/sprites/player.png`，不引用 `player_frames.png`
- 现有项目没有"角色选择"场景，TitleScene 直接开始游戏

### 3.4 这两个文件理论上不该被显示

代码层面：
- ❌ TitleScene 不加载它们
- ❌ StationScene 不加载它们
- ❌ MapScene 不加载它们
- ❌ CSS 不引用它们
- ❌ HTML 不引用它们

但 Vite 把 `public/` 整个目录暴露为静态资源根，URL 路径下 `http://localhost:5173/character_choices.png` 和 `/player_frames.png` 是可访问的。

### 嫌疑人 A：`character_choices.png` 或 `player_frames.png`（最可能）

## 5. 可能的显示路径假设

### 假设 1：用户看到的是 Vite dev server 的 public 目录列表（不太可能）

仅在用户直接访问 `http://localhost:5173/` 而游戏页未渲染时，Vite dev server 默认会列出 public/ 文件。但这不会"出现在游戏加载页面"。

### 假设 2：浏览器缓存或扩展预加载（可能）

某些浏览器扩展（如图片预取）会扫描页面 HTML 中的资源 URL 并预加载。但本项目的 HTML 不引用这两个文件，所以预取也不会发生。

### 假设 3：用户看到的是 TitleScene 的 linchen_avatar.png（最可能）

用户描述"加载页面"= TitleScene，"不该出现的素材图片"= 右上角的主角头像（v0.5.3 新加）。如果是这种情况，**这是设计而非 bug**——但需要制作人确认是否要保留。

### 假设 4：用户看到的是 Vite 启动浏览器时的初始加载画面（最可能）

`vite.config.ts` 第 7 行 `open: true` 会自动打开浏览器。浏览器在加载 main.ts 之前的 1-2 秒内显示白屏，但白屏不会显示图片。

### 假设 5：测试探针残留（不太可能）

某些探针会直接打开游戏页面截图，可能在探针报告中展示了孤儿文件。但用户描述"游戏加载页面"，应指游戏内。
